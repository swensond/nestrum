# Docker integration example

From the workspace root, run:

```bash
pnpm install --frozen-lockfile
pnpm test:integration
```

Docker must be running. The runner deploys PostgreSQL 17 and MongoDB 8 on ephemeral loopback ports, creates separate PostgreSQL resource/auth databases, and applies generated migrations through the Nestrum CLI. It tests real HTTP requests against the compiled application and admin shell. Every run has a separate Compose project and artifact directory; its containers, volumes, and generated artifacts are removed on success or failure.

`default.Project` exposes public CRUD and admin. `documents.Article` is admin-only. Both have their own schemas, owner scopes, managers, and archive action. Auth lives in `identity`, and its server-owned `staff` field controls admin access. Only the test runner promotes its disposable staff fixture; signup cannot grant staff privileges.

The example adds Prisma fragments and resource/app definitions through public Nestrum interfaces. Its Node HTTP host forwards Fetch requests to the Hono runtime. All routes, OpenAPI, admin pages, widgets, and actions are generated by existing framework packages.

Prisma 8's native emitter supports one database facade per package. The application-owned sibling packages `example-postgres` and `example-mongo` each depend on their provider facade and own that provider's generated artifacts. They export the public native runtime factories; the Mongo package also binds filter parameters to metadata codecs. PostgreSQL collections use `orm.public`; Mongo collections use `orm`. Mongo native contracts expose mapped `_id` as a 24-character ObjectId string, including in API forms. Mongo count executes an aggregate pipeline in the database.

For a persistent development deployment, start `docker compose -p nestrum-example -f apps/example/compose.yaml up --wait`. Obtain the assigned ports with `docker compose -p nestrum-example -f apps/example/compose.yaml port postgres 5432` and `port mongo 27017`. Set `AUTH_SECRET`, `INTEGRATION_POSTGRES_URL` (`nestrum_integration` database), `INTEGRATION_IDENTITY_URL` (`nestrum_identity` database), and `INTEGRATION_MONGO_URL`. Compose's local PostgreSQL credentials are `nestrum` / `integration-only`.

Build the workspace, then generate, plan, and apply migrations for each of `default`, `documents`, and `identity`:

```bash
pnpm exec nestrum db generate --database default --config apps/example/nestrum.config.mjs
pnpm exec nestrum db migrate --database default --plan --name initial --config apps/example/nestrum.config.mjs
pnpm exec nestrum db migrate --database default --config apps/example/nestrum.config.mjs
pnpm exec nestrum db status --database default --config apps/example/nestrum.config.mjs
pnpm --filter @nestrum/example start
```

Repeat the CLI commands with the other database names before starting. Open `http://127.0.0.1:3100/admin`; `PORT` changes the listener port. A trusted operator must grant a user's staff flag in the identity database before they can enter admin. SIGINT/SIGTERM stop traffic and run framework shutdown before database disconnect. Stop this deployment with `docker compose -p nestrum-example -f apps/example/compose.yaml down --volumes` when its disposable data is no longer needed.

For optional manual browser QA, run `INTEGRATION_BROWSER_QA=1 pnpm --filter @nestrum/example integration` after building. The runner pauses after native form checks and prints its local URL, disposable staff credentials, and PID. Resume with `kill -USR2 <printed-pid>` after checking the browser; the suite then finishes deletion/logout/shutdown checks and cleanup. Default integration runs never pause.
