# 0013 — Database workflow and lifecycle ownership

Accepted — Phase 15. Nestrum owns config loading and named database targeting while delegating to the pinned Prisma 8 contract/migration commands. Generation and planning remain offline, migrations live at stable per-database paths, and applying reviewed migrations is a separate command. Connections are passed through the child environment rather than persisted in generated configs or exposed in command arguments. Provider source/control-module contributions retain explicit ownership and native validation.

The portable application owns prepare/connect/configure/ready/rollback and database disconnect ordering; a runtime supplies pre-ready route registration and post-app DI disposal callbacks. This avoids a ready application whose routes later fail validation and ensures startup failure uses the same app → DI → database cleanup order as shutdown. Supplied DI/client ownership is explicit. A drain timeout preserves active resources and allows retry instead of disconnecting underneath running requests; host cancellation remains host-specific. See [workflow](../database-workflow.md) and [Phase 15](../phases/phase-15-cli-lifecycle.md).
